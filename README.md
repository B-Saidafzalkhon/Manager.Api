# Manager.Api

A REST API for managing **clients and their orders**, built with ASP.NET Core and Entity Framework Core on SQL Server.

The project was created during the Entity Framework Core block of my backend internship. Its goal is to practise a clean layered architecture (Controller → Service → Repository), dependency injection and the core EF Core features: DbContext setup, migrations, Fluent API configuration and relationships.

## Tech stack

- .NET 10, ASP.NET Core Web API (controllers)
- Entity Framework Core with the SQL Server provider
- Microsoft SQL Server 2025 (Developer edition)
- OpenAPI + Swagger UI
- JetBrains Rider

## Architecture

```
HTTP request
    │
    ▼
Controllers      HTTP only: routes, status codes, request/response DTOs
    │
    ▼
Services         business rules, mapping between entities and DTOs
    │
    ▼
Repositories     data access through EF Core, return entities
    │
    ▼
ManagerDbContext → SQL Server
```

- Every layer depends on **interfaces** (`IClientService`, `IClientRepository`, ...), registered in the DI container with a **scoped** lifetime, one instance per HTTP request, the same as the `DbContext`.
- Controllers never touch EF Core; repositories never know about API contracts.
- Entities are never returned from the API directly. Requests and responses use DTOs from `Contracts/`.

## Data model

```
Client 1 ──── * Order
```

| Entity | Key fields |
| --- | --- |
| `Client` | `Id` (Guid), `Name`, `Surname`, `Email`, `CreatedAtUtc` |
| `Order` | `Id` (Guid), `ClientId` (FK), `Note`, `CreatedAtUtc` |

Configuration is done with the **Fluent API** in separate `IEntityTypeConfiguration<T>` classes:

- `Name` and `Surname` are required, up to 100 characters.
- `Email` is required, up to 256 characters, with a **unique index**.
- `Client → Order` is a one-to-many relationship with `DeleteBehavior.Restrict`: a client with orders cannot be deleted, so order history is never lost.
- Primary keys are `Guid` values generated by EF Core (sequential GUIDs optimised for SQL Server).

## Endpoints

### Clients

| Method | Route | Description | Responses |
| --- | --- | --- | --- |
| GET | `/api/clients` | All clients | 200 |
| GET | `/api/clients/{id}` | Client by id | 200, 404 |
| POST | `/api/clients` | Create a client | 201, 400 |
| PUT | `/api/clients/{id}` | Replace a client | 204, 400, 404 |
| DELETE | `/api/clients/{id}` | Delete a client | 204, 404 |

### Orders

| Method | Route | Description | Responses |
| --- | --- | --- | --- |
| GET | `/api/clients/{clientId}/orders` | All orders of a client | 200, 404 |
| GET | `/api/clients/{clientId}/orders/{orderId}` | One order of a client | 200, 404 |
| POST | `/api/clients/{clientId}/orders` | Create an order for a client | 201, 400, 404 |

An order is only returned when it belongs to the client in the URL, so one client's orders cannot be read through another client's route.

## Getting started

### Requirements

- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- SQL Server (Developer or Express edition) with the **TCP/IP** protocol enabled
- EF Core CLI tools:

```bash
dotnet tool install --global dotnet-ef
```

### Run

1. Clone the repository:

   ```bash
   git clone https://github.com/B-Saidafzalkhon/Manager.Api.git
   cd Manager.Api
   ```

2. Check the connection string in `Manager.Api/appsettings.json`. By default it uses Windows authentication against a local SQL Server:

   ```
   Server=localhost;Database=Manager;Trusted_Connection=True;TrustServerCertificate=True
   ```

3. Create the database from the migrations:

   ```bash
   cd Manager.Api
   dotnet ef database update
   ```

4. Start the API:

   ```bash
   dotnet run
   ```

5. Open Swagger UI at `http://localhost:<port>/swagger` (the port is shown in the console on startup).

## Project structure

```
Manager.Api/
├── Configurations/   Fluent API configuration for each entity
├── Contracts/        request and response DTOs, mapping extensions
├── Controllers/      ClientsController, OrdersController
├── Data/             ManagerDbContext
├── Entities/         Client, Order
├── Migrations/       EF Core migrations
├── Repositories/     data access interfaces and implementations
├── Services/         business logic interfaces and implementations
└── Program.cs        DI registration and the HTTP pipeline
```

## What I practised

- Setting up a `DbContext` and registering it in DI
- Creating, applying, reverting and removing EF Core migrations
- Tracking vs. `AsNoTracking` queries, updates through the change tracker
- Fluent API configuration: lengths, required fields, unique indexes
- One-to-many relationships, foreign keys and delete behaviour
- The Repository and Service patterns with dependency injection
- Correct HTTP semantics: 201 with `CreatedAtAction`, 204 for PUT and DELETE, 404 handling
